# Участие в разработке

Спасибо за интерес к проекту. Issues и pull request'ы можно писать по-русски или по-английски.

## Сборка и проверка

Нужны Windows 10/11, Node.js 22.13+ и Git.

```bash
npm install
npm run typecheck   # TypeScript для обоих пакетов
npm test            # все тесты (vitest)
npm run build       # сборка приложения (esbuild) в packages/app/dist
npm run demo        # окно виджета на симулированных данных
npm run smoke       # демо со снимками экрана в ./smoke и отчётом report.json
```

Перед pull request'ом запустите `npm run typecheck` и `npm test`: то же самое проверяет CI на каждый push.

## Как устроен код

Короткая карта и формулы — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Главное:

* `packages/core` — чистый TypeScript без Electron: расписание, бюджет, статистика, детектор. Менять формулы нужно здесь, вместе с тестами.
* Каждый источник данных — один файл-адаптер в `packages/app/src/providers` за интерфейсом `UsageProvider`. Если claude.ai изменит ответ, правится только `claude.ts`.
* Тесты работают на **обезличенных** фикстурах. Новые образцы ответов нужно обезличивать: без cookie, токенов, идентификаторов организации и аккаунта, почт, текстов разговоров.
* Код, интерфейс и документация на русском. Комментарии объясняют, почему так сделано, а не что делает строка.

## Что подходит для pull request'а

* Исправления ошибок с тестом, который воспроизводит проблему.
* Новые провайдеры через `UsageProvider`. Пример — чтение логов ChatGPT Desktop (Codex) в `packages/app/src/providers/chatgpt.ts` и `codexFiles.ts`: запись лога с прошедшим временем сброса означает сброшенное окно.
* Улучшения интерфейса и документации.
* Измерения на других тарифах: если ответ claude.ai у вас отличается, запустите шаг 0 (дашборд → «Настройки» → «Запустить спайк») и приложите **обезличенный** отчёт к issue.

## Чего не нужно присылать

Не публикуйте в issues и pull request'ах значения cookie, токены, содержимое `%APPDATA%\LimitBudget` и непросмотренные отчёты шага 0: в них есть ваши проценты использования и тариф.
Сообщения об уязвимостях отправляйте по правилам из [SECURITY.md](SECURITY.md), а не публичным issue.
