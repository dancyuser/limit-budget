# Устройство и расчёты

Документ для тех, кто читает или меняет код. Установка и работа с виджетом описаны в [INSTALL.md](INSTALL.md) и [USAGE.md](USAGE.md).

## Как это считается

Формулы лежат в `packages/core/src`. Ядро не зависит от Electron: это чистый TypeScript, который проверяется обычными тестами.

| Что | Формула / правило | Файл |
| --- | --- | --- |
| Окно недели | от `resets_at` недельного лимита минус 7 суток; без `resets_at` — календарная неделя | `budget.ts` |
| Цель T(t) | `100·(1 − r)·a(t)/A`, r = 0,1; A, a — взвешенные активные часы окна и пройденные | `budget.ts`, `schedule.ts` |
| Подсказка на остаток | ρ = (100(1 − r) − u)/(A − a); D = u + ρ·(часы до конца дня) | `budget.ts` |
| Статус | `u > T + δ` — выше траектории, `u < T − δ` — есть запас (δ = 5 п.п.) | `budget.ts` |
| k | медиана Δ недели / Δ 5ч по парам снимков, отдельно в пик и вне пика; до накопления — ручное (0,15) | `ticks.ts` |
| Доступно сейчас | `X = min(100 − u5ч, (S − u7д)/k)`, S — цель недели на конец блока; `C = (1 − r)/k` | `budget.ts` |
| Остаток времени | `H_left = (100 − u)/v̄`, v̄ — медиана за 14 рабочих дней; «не хватит», если меньше оставшихся часов | `replay.ts`, `budget.ts` |
| Пик | профиль в `America/Los_Angeles` (05:00–11:00 по будням), пересчёт в UTC+3 через `Intl` | `peak.ts` |
| Время работы | интервалы роста процента (пауза короче порога склеивается) и время завершённых задач | `ticks.ts`, `attribution.ts` |
| Детектор | «тяжёлый час» по MAD, сдвиг недельного показателя по CUSUM; всегда «возможное изменение» | `anomaly.ts` |

Режим «Отпуск» выключает цели и все сигналы целиком; шкалы процентов и время сброса остаются, статистика копится с пометкой.

Расписание по умолчанию: пн–пт, 10:00–14:00 и 15:00–19:00 в UTC+3 (40 активных часов в неделю), выходные в бюджет не входят. Расписание и исключения хранятся в базе и меняются в настройках дашборда.

### Решения там, где требования допускали несколько толкований

* **«Превышение лимита»** подаётся, когда «доступно сейчас» дошло до нуля внутри блока либо недельный расход дошёл до недельной цели
  100·(1 − r). Предупреждение «выше траектории» подаётся раньше, при `u > T + δ`.
* **«5-часовое окно закончится раньше блока»** — прогноз по текущему темпу: окно исчерпается раньше конца блока (и раньше своего сброса).
* **k по умолчанию 0,15** (C = 6 окон из 10), пока не накоплено 5 пар в соответствующем режиме; меняется в настройках, пустое значение — считать только по окну.
* **Обед и выходные**: «доступно сейчас» считается относительно ближайшего следующего блока. Поэтому вне рабочего времени число «доступно» может быть больше, чем осталось в текущем 5-часовом окне.
* **Ручная отметка модели** действует до следующей отметки (до 12 часов), автоматическая — 5 минут.

## Структура репозитория

```
packages/core   чистый TS: расписание, пик, бюджет, k, сигналы, статистика, детектор, симулятор, UsageProvider
packages/app
  src/shared    SQLite (db.ts), сервис опроса (service.ts), настройки, экспорт, IPC-типы, разбор прокси
  src/providers claude.ts (один файл), chatgpt.ts (заглушка на фикстурах), fixtures.ts
  src/main      Electron: окна, трей, вход в claude.ai, звуки и уведомления, спайк, запасной вход
  src/renderer  виджет, дашборд, окно входа (TS без фреймворка, SVG-графики)
  src/cli       командная строка
scripts/start.mjs  запуск Electron с любыми ключами независимо от оболочки
docs            документация и снимки экрана
```

Принципы: адаптер каждого источника лежит в одном файле; тесты работают на обезличенных фикстурах; режим реплея прогоняет
сохранённую историю через калькулятор; ядро не зависит от Electron; любой провайдер подключается только через интерфейс `UsageProvider`.

### Интерфейс провайдера

Провайдер описывает свои возможности (`capabilities`: окна, поверхности, срезы по моделям) и отдаёт снимки окон (`poll`), а при наличии — активность и задачи.
Всё остальное (расчёт, база, виджет) от конкретного провайдера не зависит. Чтобы подключить новый источник, нужен один файл в `packages/app/src/providers`
и контрактные тесты на обезличенных образцах.

### База данных

SQLite через встроенный `node:sqlite`, нативных зависимостей нет. Таблицы: `limit_snapshot`, `activity_interval`, `task_run`, `model_sample`,
`attribution`, `schedule`, `schedule_exception`, `mode_state`, `provider_config`, `settings`, `event_note`, `anomaly`, `usage_event`,
`ingest_cursor` (+ `daily_aggregate`). Везде есть поле `provider`, поэтому добавление провайдеров не требует новых таблиц.
Сырая активность хранится 90 дней, снимки и дневные агрегаты бессрочно.

### Вход и сеть

Все запросы к claude.ai идут через Chromium внутри Electron, в одной постоянной сессии `persist:claude`: скрытая страница опроса, окно входа и всплывающие окна
(например, «Войти через Google») используют один профиль, один прокси и одну строку User-Agent без токена `Electron/…`. Запросы выполняются изнутри страницы,
что обходит проверку Cloudflare. Опрос идёт раз в минуту, страница перезагружается раз в час, чтобы продлевать сессию.

## Известные ограничения

1. **Эндпоинт использования claude.ai неофициальный.** Путь `/api/organizations/{org}/usage` и поля `five_hour.utilization`, `seven_day.resets_at`
   взяты из сторонних проектов и подтверждены на тарифе Pro. Адаптер терпим к вариантам имён, а при несовпадении формы показывает ошибку, а не нули.
2. **Ещё не проверено:** 7 дней опроса без пропусков (`cli gaps`), перетаскивание и смена монитора, поведение 5-часового окна (стартует ли оно с первого сообщения).
3. **Запасной вход через сессию Claude Desktop** (DPAPI + AES-GCM) реализован, в фоне выключен по умолчанию; перед использованием сверьтесь с условиями сервиса.
4. **Определение модели и режима в Claude Desktop** автоматически не реализовано. Пока работает ручная отметка; без неё разбивка помечается как оценка.
5. **Разбивка недели по продуктам** (`seven_day_breakdown`: Claude Code, Чаты, Cowork) приходит в ответе, но адаптер её пока не читает.
6. **ChatGPT Desktop (Codex)** читается только из локальных логов: они пишутся, пока приложение работает, так что данные могут быть старыми (устаревшее окно показывается как пустое). Облачные задачи и обычные чаты ChatGPT в логах не отражаются; лимиты чатов ChatGPT локально не доступны.
7. Установщик не подписан: SmartScreen покажет предупреждение.
